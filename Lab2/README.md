## 功能特性

### 必需功能
1. **连接管理**: 三次握手建立连接，四次挥手断开连接
2. **差错检测**: 16位互联网校验和（Internet Checksum）
3. **确认重传**: 选择确认（SACK）和累积确认结合
4. **流量控制**: 滑动窗口机制，可配置窗口大小
5. **拥塞控制**: TCP RENO算法（慢启动、拥塞避免、快速重传、快速恢复）

### 扩展功能
- **SACK支持**: 最多8个选择确认块，提高重传效率
- **性能统计**: 吞吐量、丢包率、重传次数等详细统计
- **参数可配置**: 窗口大小、丢包率等可通过命令行调整
- **多架构支持**: 自动检测并编译ARM64/x64版本

## 协议设计

### 数据包格式

```
+-------------------+
|   RDT Header      |  12 bytes
+-------------------+
|   Data Payload    |  0-1024 bytes
+-------------------+
```

### RDT Header (12 bytes)

| 字段 | 大小 | 说明 |
|-----|------|-----|
| seq | 4B | 序列号 |
| ack | 4B | 确认号 |
| len | 2B | 数据长度 |
| checksum | 2B | 校验和 |
| flags | 1B | 控制标志 (SYN/ACK/FIN/SACK) |
| window_size | 1B | 接收窗口（单位：包） |
| sack_count | 1B | SACK块数量 |
| reserved | 1B | 保留 |

### SACK 扩展

ACK 包可携带最多 8 个 SACK 块：

```cpp
struct SACKBlock {
    uint32_t start;  // 已接收数据起始序号
    uint32_t end;    // 已接收数据结束序号
};
```

## 常见问题

**Q: CMake 找不到？**
A: 确保已安装 CMake 并添加到 PATH。

**Q: 编译失败？**
A: 检查是否安装了编译器（Visual Studio/MinGW）。

**Q: ARM64 构建失败？**
A: 确保安装了 Visual Studio 的 ARM64 工具链。

**Q: 连接建立失败？**
A: 检查是否先启动了接收端，以及防火墙设置。

**Q: 性能很差？**
A: 
- ARM 设备：使用 ARM64 原生版本而非 x64 仿真
- 增大窗口大小（如128）
- 降低丢包率

**Q: 收到的文件不完整？**
A: 检查校验和错误，可能是网络问题或程序bug。

## 技术细节

### 多线程架构（发送端）

- **主线程**: 读取文件，发送数据包
- **监听线程**: 接收ACK，更新拥塞窗口
- **定时器线程**: 检查超时，触发重传

### 单线程架构（接收端）

- 阻塞接收数据包
- 验证校验和
- 缓存乱序数据
- 发送SACK确认

### 拥塞控制状态机

```
慢启动 → 拥塞避免 ⇄ 快速恢复
   ↑                    ↓
   └──────超时──────────┘
```
