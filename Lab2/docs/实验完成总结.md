## 📊 测试参数说明

### 接收端参数

```bash
receiver.exe [接收窗口大小]
```

示例：
```bash
receiver.exe 32    # 接收窗口32个包
receiver.exe 128   # 接收窗口128个包
```

### 发送端参数

```bash
sender.exe [发送窗口] [丢包率] [文件名] [-v]
```

示例：
```bash
sender.exe 64 0.0 test.txt          # 窗口64，无丢包
sender.exe 32 0.05 myfile.dat       # 窗口32，5%丢包
sender.exe 128 0.1 data.bin -v      # 窗口128，10%丢包，详细日志
```

## 🔬 核心技术亮点

### 1. 选择确认（SACK）

相比原始版本的累积确认，新版本实现了SACK：

**优势**：
- ✅ 减少不必要的重传
- ✅ 提高丢包环境下的性能
- ✅ 更精确的丢包恢复

### 2. TCP RENO拥塞控制

完整实现4个状态：

```
慢启动 → 拥塞避免 ⇄ 快速恢复
   ↑                    ↓
   └──────超时──────────┘
```

### 3. 性能统计

自动统计：
- 总字节数
- 总包数
- 重传次数
- 重复ACK次数
- 超时次数
- 传输时间
- **平均吞吐率（Mbps）** ⭐

### 4. 丢包率模拟

支持0%-100%任意丢包率模拟，用于：
- 测试协议健壮性
- 评估不同丢包率下的性能
- 验证重传机制

## 📞 常见问题

### Q1: 如果编译失败？

**A**: 检查是否安装了MinGW g++，并确保支持C++11：
```bash
g++ --version
```

### Q2: 连接建立失败？

**A**: 
1. 确保先启动接收端
2. 检查防火墙设置
3. 确认8888端口未被占用

### Q3: 性能很差？

**A**: 
1. 增大窗口大小（如128）
2. 降低丢包率
3. 使用本地回环测试

### Q4: 文件传输不完整？

**A**: 
1. 检查控制台是否有校验和错误
2. 确认发送端显示"All ACKs received"
3. 对比文件大小
