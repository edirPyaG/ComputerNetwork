## 二、协议设计

### 2.1 协议头部结构

采用紧凑的协议头部设计（12字节），使用 `#pragma pack(1)` 确保字节对齐：

```cpp
struct RDTHeader {
    uint32_t seq;          // 序列号 (4字节)
    uint32_t ack;          // 确认号 (4字节)
    uint16_t len;          // 数据长度 (2字节)
    uint16_t checksum;     // 校验和 (2字节)
    uint8_t  flags;        // 控制标志 (1字节)
    uint8_t  window_size;  // 接收窗口 (1字节)
    uint8_t  sack_count;   // SACK块数量 (1字节)
    uint8_t  reserved;     // 保留字段 (1字节)
};
```

**控制标志位**:
- `FLAG_SYN (0x01)`: 同步序号，建立连接
- `FLAG_ACK (0x02)`: 确认应答
- `FLAG_FIN (0x04)`: 结束连接
- `FLAG_SACK (0x08)`: 选择确认

### 2.2 选择确认（SACK）机制

为了提高重传效率，实现了SACK机制：

```cpp
struct SACKBlock {
    uint32_t start;    // 已接收数据块起始序号
    uint32_t end;      // 已接收数据块结束序号
};
```

接收端在ACK包中携带最多8个SACK块，告知发送端哪些乱序数据已收到，避免不必要的重传。

### 2.3 连接管理

#### 2.3.1 三次握手建立连接

```
发送端                         接收端
  |                               |
  |------ SYN (seq=0) ----------->|
  |                               |
  |<-- SYN-ACK (seq=0,ack=1) -----|
  |                               |
  |------ ACK (ack=1) ----------->|
  |                               |
  |      连接建立，开始传输数据      |
```

#### 2.3.2 四次挥手关闭连接

```
发送端                         接收端
  |                               |
  |------ FIN ---------------->|
  |                               |
  |<------ ACK -----------------|
  |                               |
  |<------ FIN-ACK --------------|
  |                               |
  |      连接关闭                  |
```

### 2.4 差错检测

采用标准的Internet校验和算法（16位）：

1. 将校验和字段置0
2. 将数据按16位字求和
3. 将进位加到低16位
4. 对结果取反码

接收端使用相同算法验证数据完整性，校验失败则丢弃数据包。

## 三、可靠传输机制

### 3.1 确认重传策略

#### 3.1.1 累积确认 + 选择确认

- **累积确认**: ACK号表示期望接收的下一个序号
- **选择确认**: SACK块标识已接收的乱序数据

#### 3.1.2 超时重传

发送端为每个数据包维护计时器（默认500ms），超时未收到ACK则重传：

```cpp
if (timeout) {
    ssthresh = cwnd / 2;    // 慢启动阈值减半
    cwnd = MSS;              // 拥塞窗口重置为1个MSS
    重传最早未确认的数据包;
}
```

#### 3.1.3 快速重传

接收到3个重复ACK时立即重传：

```cpp
if (dupACKcount == 3) {
    ssthresh = cwnd / 2;
    cwnd = ssthresh + 3 * MSS;  // 进入快速恢复
    重传丢失的数据包;
}
```

### 3.2 流水线传输

采用滑动窗口机制支持流水线传输：

```
发送窗口 = min(拥塞窗口, 接收窗口, 配置窗口)
```

发送端可以在未收到确认的情况下，连续发送窗口大小内的多个数据包。

## 四、流量控制

接收端通过窗口通告机制实现流量控制：

```cpp
// 接收端计算可用缓冲区
int buffer_usage = packet_buffer.size();
int available = RECV_WINDOW_SIZE - buffer_usage;
ack_pkt.header.window_size = max(0, available);
```

发送端据此调整发送速率，防止接收端缓冲区溢出。

## 五、拥塞控制（TCP RENO）

### 5.1 状态转换图

```
        +-------------+
        | Slow Start  |  cwnd < ssthresh
        | cwnd *= 2   |  (指数增长)
        +-------------+
              |
              | cwnd >= ssthresh
              v
        +-------------------+
        | Congestion        |  cwnd += MSS/cwnd
        | Avoidance         |  (线性增长)
        +-------------------+
              |
              | 3 dup ACKs
              v
        +-------------------+
        | Fast Recovery     |  ssthresh = cwnd/2
        |                   |  cwnd = ssthresh + 3*MSS
        +-------------------+
              |
              | Timeout
              v
        回到 Slow Start (cwnd = MSS)
```

### 5.2 算法实现

```cpp
// 收到新ACK
if (ack > base) {
    if (cwnd < ssthresh) {
        // 慢启动：指数增长
        cwnd += MSS;
    } else {
        // 拥塞避免：线性增长
        cwnd += MSS * MSS / cwnd;
    }
}
// 收到重复ACK
else if (dupACKcount == 3) {
    // 快速重传 & 快速恢复
    ssthresh = cwnd / 2;
    cwnd = ssthresh + 3 * MSS;
    重传;
}
```

## 六、实现细节

### 6.1 多线程架构（发送端）

```
+------------------+
|   主线程         |  读取文件，发送数据包
+------------------+
         |
         |  共享: send_buffer, cwnd, base
         |
    +----+----+
    |         |
+--------+ +--------+
| 监听   | | 定时器 |
| 线程   | | 线程   |
+--------+ +--------+
    |         |
    |         |
接收ACK   检查超时
更新cwnd  触发重传
```

使用 `std::mutex` 保护共享变量，确保线程安全。

### 6.2 单线程架构（接收端）

```
while(true) {
    recvfrom();           // 阻塞接收
    验证校验和;
    处理控制包 (SYN/FIN);
    
    if (seq == expected_seq) {
        写入文件;
        检查缓冲区;
    } else {
        缓存乱序数据;
    }
    
    发送SACK确认;
}
```

### 6.3 关键数据结构

**发送缓冲区**:

```cpp
struct SentPacket {

```

## 九、实验结论

### 9.1 成果总结

本实验成功实现了基于UDP的可靠传输协议，具备以下特性：

1. ✅ **连接管理**: 三次握手建立连接，四次挥手关闭连接
2. ✅ **差错检测**: 16位Internet校验和
3. ✅ **确认重传**: 累积ACK + 选择ACK (SACK)，支持超时重传和快速重传
4. ✅ **流量控制**: 接收窗口通告机制
5. ✅ **拥塞控制**: TCP RENO算法（慢启动、拥塞避免、快速恢复）
6. ✅ **性能测试**: 支持可配置窗口大小和丢包率模拟

### 9.2 改进空间

1. 可实现更精确的RTT估计和动态RTO调整
2. 可添加延迟确认（Delayed ACK）减少ACK数量
3. 可实现Nagle算法减少小包传输
4. 可添加乱序队列优化缓冲区管理
